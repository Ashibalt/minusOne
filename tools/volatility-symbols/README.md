# Volatility 3 kernel symbol cache

Committed so `memory.volatility` works fully offline out of the box. Volatility 3
maps kernel structures through ISF symbol tables; without one matching the capture,
every Windows plugin refuses with "symbol table requirement not fulfilled".

Layout follows vol3's symbol search: `windows/<pdb-name>/<GUID-AGE>.json.xz`.
The provider mounts this directory read-only and passes it via `vol -s`.

## What is covered here

| File | Covers | Source |
| --- | --- | --- |
| `windows/ntoskrnl.pdb/32962337F0F646388B39535CD8DD70E8-2.json.xz` | Windows XP SP2 x86 kernel — exactly the official vol3 test corpus image `win-xp-laptop-2005-06-25.img` | Generated by volatility3 2.28.0 downloading `ntkrnlpa.pdb` from msdl.microsoft.com and converting it (one-time online step below) |

sha256: `7055063d1dd7296f0ab2a72b32384e3f52960b61950afe4262bfb383f5bc835c` (179,712 bytes)

the conversion is performed by volatility3 itself (Volatility Software License,
https://www.volatilityfoundation.org/license/vsl-v1.0).

## Extending the cache for another capture

One-time online generation (the generated ISF lands in the container and is copied out):

```bash
docker create --name volsymgen --entrypoint sh \
  --volume "<absolute path to the memory image>:/image:ro" \
  minusone/volatility3:2.28.0 \
  -c "vol -q -r json -f /image windows.info > /dev/null && echo SYMBOLS_OK"
docker start -a volsymgen
docker cp volsymgen:/usr/local/lib/python3.12/site-packages/volatility3/symbols/windows tools/volatility-symbols/windows-new
# merge windows-new/* into windows/, then: docker rm volsymgen
```

Fallback for many images at once: the foundation's full Windows pack (~801 MB),
`node scripts/fetch-volatility-data.mjs symbols` (extracts to
`.minusone/datasets/volatility-symbols`, which the provider probes as a second
symbol location).
